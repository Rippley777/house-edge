## Event lifecycle and operational findings

Browser entry point initializes the vendored SDK only with configured key/endpoint and production mode (development requires opt-in). It emits session_start and page_view, batches with stable UUIDs, and sends nonblocking text/plain POSTs. Collector validates 100-event/64 KiB limits, exact project/key/origin, seven-day timestamp age/five-minute future skew, and database-backed per-project rate limits. Repository transaction persists events and session/user/day projections before returning accepted counts. Optional geographic staging follows successful persistence. Authenticated dashboard reads query the same database; responses are no-store.

House Edge is an npm workspace with Next.js 16, React, TypeScript, SQLite locally and Azure SQL in production. Existing tests use node:test/tsx and Playwright. Build invokes SDK bundling then Next.js. Deployment uses the existing Azure GitHub Actions workflow; migrations require separate DDL access and are not applied by a code deployment. No second service is needed.

Production local configuration has distinct public keys and project keys (`stacked-deck`, `rippley-labs`), both targeting `https://house-edge-daac2bd8.azurewebsites.net/api/collect`. Secret values were not printed. A live authenticated API inspection returned **503** from `/api/health` and a database-configuration error from `/api/projects`. Therefore project registration, live persistence and dashboard acceptance cannot yet be confirmed. An actual browser opened rippleylabs.com and navigated to `/downloads`; this is a visit attempt, not proof of ingestion.

Projects already have stable IDs, origin lists, active state and creation timestamps. Retention and authorization are workspace-wide (single owner), not per-project. Geography currently exposes fine aggregate buckets down to one event. Client-provided `country` is stored in the legacy event column even though the newer enriched geography ignores untrusted context. Error message/stack fields currently pass free text unchanged. SDK retry delay is capped, but attempts are unlimited. Existing error summaries sum per-group session counts and can overcount the same session.

## Smallest safe change and cross-application impact

- Applications affected: House Edge; browser SDK consumers Stacked Deck and Rippley Labs website when upgraded.
- Contracts affected: additive event receive timestamp and aggregate response fields; browser SDK patch version. Existing project IDs and event names remain.
- Data ownership: all analytics stay in House Edge; applications retain their domain data.
- Events added or changed: no new required event names; error category/release metadata remain optional.
- Migration required: additive House Edge migration for receive time; old rows remain unknown rather than inventing timestamps.
- Backward-compatibility risk: low-volume fine geography becomes suppressed; errors are scrubbed before grouping; SDK exhausts retries rather than retrying forever.
- Deployment order: migration, House Edge, then consumer SDK builds. Cloudflare relay only after existing route/key configuration is verified. No credential rotation, destructive infrastructure operation, or production redeployment is performed without the established deployment process.
